Architecture Principles — Rules / Guidelines
No Single Point of Failure

Principle: If one component fails, the whole system should not stop.

Instead of a single database server:

Application
     |
Database Server

Use primary + replica:

Application
     |
Primary Database
     |
Replica Database

If one database goes down, another can take over.

SaaS is Preferred

Principle: Use existing cloud services instead of building everything yourself.

Instead of writing your own email service in Java:

public class EmailService {
    // thousands of lines of code
}

Use a SaaS provider such as SendGrid or Mailchimp. Your Java code simply calls their API.

Best-of-Breed Applications

Principle: Choose the best tool for each job.

  • Java Spring Boot for backend
  • PostgreSQL for data
  • Redis for caching
  • Kafka for messaging

Each tool is selected because it excels at a specific task.

Deep Dive — Load Balancing

A Load Balancer is a component that distributes incoming client requests across multiple servers to improve scalability, availability, reliability and performance.

Network Load Balancer (NLB) — Layer 4

A Network Load Balancer (NLB) works at Layer 4 of the OSI model. It distributes traffic based on network information such as IP addresses, ports, and TCP/UDP protocols without inspecting the HTTP request.

Because it does not process application-layer data, it provides very high performance and low latency.

It is commonly used for TCP/UDP services like databases, Kafka, and Redis. For HTTP-based microservices that require path- or host-based routing, an Application Load Balancer is typically the better choice.

An NLB is used when a single service receives too much traffic for one server to handle. Multiple instances of the same service are deployed, and the NLB distributes incoming TCP or UDP connections across those instances.

Since it operates at Layer 4, routing decisions are based on IP addresses and port numbers rather than inspecting the HTTP request.

When to use NLB

  • Extremely high throughput.
  • Raw TCP or UDP traffic.
  • Low latency is critical.
  • No need to inspect HTTP requests.

Examples

  • Database connections
  • Redis
  • Kafka
  • Gaming servers
  • MQTT
  • SMTP
Application Load Balancer (ALB) — Layer 7

An Application Load Balancer (ALB) works at Layer 7 (Application Layer) and routes traffic based on HTTP/HTTPS request details such as URL path, hostname, headers, or cookies.

It is ideal for web applications and microservices.

When to use ALB

  • Building REST APIs.
  • Running microservices.
  • Hosting web applications.
  • Routing based on URLs or hostnames.
  • Performing SSL termination.
  • Supporting authentication integrations.

Deep Dive — Database Indexing

An index is a separate data structure, usually a B+ Tree, that stores indexed column values along with pointers to the corresponding table rows. This allows the database to find data quickly without scanning the entire table.

For structured data such as IDs, dates and salaries, databases use B+ Tree indexes.

Trade-off — advantages

  • Faster SELECT
  • Faster WHERE
  • Faster JOIN
  • Faster ORDER BY

Trade-off — disadvantages

  • Slower INSERT
  • Slower UPDATE
  • Slower DELETE
  • Extra storage required
B+ Tree vs Inverted Index

For searching text across many fields, such as Google or product search, systems use search engines such as Solr or Elasticsearch, which use inverted indexes.

An inverted index maps each word (token) to the list of documents containing that word. This enables extremely fast full-text searches without scanning every document.

30-Second Interview Answer
“An index is a separate data structure, usually a B+ Tree, created on one or more columns. It stores the indexed values and pointers to the actual table rows. Instead of scanning the entire table, the database searches the index first and then directly accesses the matching row. This improves read performance from roughly O(n) to O(log n), at the cost of additional storage and slower insert, update, and delete operations.”
