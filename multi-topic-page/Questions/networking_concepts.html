3
API Gateway — What it adds▼

Gateway provides broader API management beyond just routing:

  • Authentication & Authorization
  • Rate limiting
  • API versioning
  • Request transformation
  • API policies
ALB → Traffic / Target balancing Gateway → API management

You can have both: Client → Gateway → ALB → Instances

4
Gateway + Service Discovery▼

If Gateway has service discovery, a separate LB may not be needed — Gateway can discover instances and do client-side load balancing.

"We don't necessarily need a separate LB. The gateway can perform discovery and instance selection. A separate LB is useful for infrastructure-level distribution, centralized health checks, or cloud-managed traffic."
5
Internal Service Communication▼

Not every service call needs to go through Gateway. Internal options:

Order → Discovery → Payment (direct) Order → Internal LB → Payment (load balanced) Order → Kafka/RabbitMQ → Payment (async)
"I would keep the API Gateway as the client-facing entry point rather than forcing all internal traffic through it."
6
Multi-Region Architecture▼
Users → Global DNS → US Gateway → ALB → US1/US2 → EU Gateway → ALB → EU1/EU2 → Asia Gateway → ALB → AS1/AS2

Regional HA vs Global HA

Regional: LB handles instance failures within a region.

Global: DNS reroutes traffic when an entire region fails.

🌍 DNS & Geo Routing
1
How does GeoDNS work?▼

DNS is configured with multiple IPs for the same hostname. GeoDNS / latency-based routing returns the IP of the nearest or healthiest regional LB.

api.example.com → US LB → 52.10.10.10 EU LB → 18.20.20.20 Asia LB → 13.30.30.30 User in Germany asks DNS → gets EU LB IP (18.20.20.20) User in Japan asks DNS → gets Asia LB IP (13.30.30.30)

Full Flow

User (Germany) → DNS → EU LB → API Gateway → Service

Providers: Route 53, Cloudflare, Azure DNS

2
Who decides which region?▼

A global DNS / traffic-management layer makes the decision using policies: latency, geography, health, failover, weighted routing.

"The global traffic-management layer routes the client to the optimal healthy region based on latency, geography, or configured failover policies."

Region failure?

Traffic management detects unhealthy region → routes to another healthy region → global high availability.

🔒 Private IPs & Architecture
1
Public IP vs Private IP▼
Public IPPrivate IP
Accessible fromInternetInternal network only
Example88.88.88.110.0.0.1
Used byClients (users)Servers (internal)

Internet ❌ cannot access private IP directly.

2
How traffic flows▼
User → mywebsite.com ↓ DNS 88.88.88.1 (Public IP = Load Balancer) ↓ Load Balancer decides: which server? ↓ Server1 (10.0.0.1) or Server2 (10.0.0.2) ← Private IPs 🔒

Why Private IP?

  • Security — clients can't directly hit servers
  • Control — LB controls routing, distribution, failover
  • Cost & Scaling — private IPs are cheap and unlimited inside network

Cloud Example

Internet → ALB (Public IP) → Private EC2 instances (10.x.x.x) Same in: Azure (VNet), GCP (VPC)
3
Interview Answer▼
"Private IPs are used for internal communication between servers within a network. In a typical architecture, clients connect to a load balancer using a public IP, and the load balancer routes requests to backend servers using their private IPs. This improves security by preventing direct access to servers and allows better control over traffic routing."
