🔐 Security — JWT Authentication

Stateless authentication, token structure, creation, validation & best practices

1
What is JWT?▼

JWT (JSON Web Token) is a compact, URL-safe token for stateless authentication. Instead of storing sessions on the server, the client sends the token with every request.

It contains user claims (username, roles) and is digitally signed to prevent tampering.

Advantages

  • ✅ Stateless — no server session storage
  • ✅ Scalable — works across multiple servers
  • ✅ Great for Microservices
  • ✅ Faster request processing

Disadvantages

  • ❌ Difficult logout (token remains valid until expiry)
  • ❌ Token expiration management required
2
JWT Token Format▼
xxxxx.yyyyy.zzzzz ↑ ↑ ↑ Header Payload Signature

1. Header

{"alg": "HS256", "typ": "JWT"}

2. Payload (Claims)

{ "sub": "amit", // subject — who the token is for "role": "ADMIN", "iat": 1722144000, // issued at "exp": 1722147600 // expiration }

Standard Claims

ClaimMeaning
issIssuer — who created the token
subSubject — who it's for
expExpiration time
iatIssued at
nbfNot valid before
jtiJWT ID

3. Signature

a. Define secret key b. Encode: base64UrlEncode(header) + "." + base64UrlEncode(payload) c. Sign: HMAC_SHA256(encodedData, secretKey)
3
How JWT is Created (Spring Security)▼
1. User sends username + password to /login 2. Spring Security authenticates (AuthenticationManager + UserDetailsService + PasswordEncoder) 3. Collect claims: username (sub), roles, issued at, expiration 4. Create Header (algorithm + type) 5. Create Payload (claims) 6. Base64URL encode header + payload 7. Generate signature using secret key 8. Final JWT = Header.Payload.Signature 9. Return to client

Code Example

String token = Jwts.builder() .subject(username) .claim("role", role) .issuedAt(new Date()) .expiration(expiryDate) .signWith(secretKey) .compact();
4
Complete Authentication Flow▼
1. User logs in (username + password) 2. Server verifies → generates JWT 3. Client stores token 4. Every subsequent request: Authorization: Bearer <JWT> 5. Server validates signature + expiration 6. Access granted ✅
5
Is JWT encrypted?▼

No. JWT is Base64URL encoded, not encrypted. Anyone can decode the header and payload.

The signature protects against modification (tampering), not reading.

JWTs are decoded and verified, not decrypted. The server decodes the payload and checks the signature using the secret key.
6
Why doesn't the server trust the client?▼

The client can modify or forge a token. Every incoming JWT must be verified for:

  • Signature validity
  • Expiration (exp claim — JJWT auto-validates)
  • Issuer (optional)
  • Audience (optional)

JWT is verified inside the Spring Security Filter Chain.

Invalid/expired JWT → 401 Unauthorized

7
Why is JWT called Stateless?▼

The server does not store user session data. Every request contains all required authentication information inside the JWT itself.

8
Best Practices▼
  • Use HTTPS
  • Keep access tokens short-lived (e.g., 15 minutes)
  • Use refresh tokens
  • Store refresh tokens securely (HttpOnly cookies)
  • Never store passwords or sensitive data in JWT claims
  • Validate signature and expiration on every request
  • Rotate signing keys periodically
  • Consider RS256 for distributed systems (services only need public key to verify)
